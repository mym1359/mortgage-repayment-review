# Domain docs

This project uses one domain glossary at `GLOSSARY.md` and keeps architecture decision records in `docs/adr/`.

Before exploring the project, read the glossary and any decision records relevant to the work, when available. Use glossary terms in issues, specs, test names, and implementation discussions. Record gaps for the `domain-modeling` skill to resolve as terms and decisions emerge. If proposed work conflicts with a recorded decision, name the decision and describe the conflict.
